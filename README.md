# Навыки работы с GitHub

**Git** — это система контроля  версий, которая является обязательным инструментом в арсенале любого  разработчика. **С Git:** У вас одна папка проекта и полная история всех изменений.

#### Git

- ✅ Сохраняет историю изменений в вашем проекте
- ✅ Позволяет откатываться к предыдущим версиям
- ✅ Обеспечивает командную работу без конфликтов
- ✅ Создает "резервные копии" вашего кода

## Регистрация и использование GitHub 

### Шаг 1: Регистрация аккаунта

Для регистрации на [GitHub](https://github.com/):

1. Перейдите на сайт и нажмите кнопку **«Sign up»** в правом верхнем углу
2. Введите действующий email, создайте пароль и уникальный логин
3. Подтвердите электронную почту, введя 8-значный код из письма
4. Решите капчу (головоломку) и нажмите **«Create account»**
5. Выберите бесплатный тариф **Free**, пропустив персонализацию (**Skip personalization**)

После этого вы попадете в личный кабинет и сможете создавать репозитории.

### Шаг 2: Создание первого репозитория

#### Создание нового репозитория

1. **Войдите в GitHub** и нажмите кнопку **«+»** в правом верхнем углу
2. **Выберите «New repository»** из выпадающего меню

#### Заполнение информации

- **Repository name**: укажите название репозитория (обязательно)
- **Description**: добавьте описание проекта (необязательно)
- **Visibility**: выберите видимость:
  - **Public** — виден всем
  - **Private** — только вам и выбранным пользователям

#### Дополнительные настройки

- **Initialize with a README** — автоматически создаст файл README.md (рекомендуется)
- **Add .gitignore** — выберите шаблон для игнорирования ненужных файлов
- **Choose a license** — выберите лицензию для проекта

После нажатия **«Create repository»** репозиторий будет создан.

### Шаг 3: Работа с файлами в репозитории

#### Редактирование README.md

Файл **README.md** автоматически создается, если вы выбрали соответствующую опцию при  создании репозитория. В этом файле описывается цель создания проекта.

**Важно:** Расширение **.md** означает, что файл использует язык разметки Markdown для форматирования текста.

Пример базовой разметки Markdown:


```markdown
# Самый большой заголовок (занимает всю строку)
## Заголовок поменьше
### Еще меньший заголовок

**жирный текст внутри предложения**

*курсивный текст*

- Элемент списка
- Еще один элемент списка

#```
убери # и # тогда здесь можно вставить фрагмент кода
#```

```



Чтобы отредактировать файл:

1. Нажмите на значок **карандаша** 📝  (Edit this file) в правом верхнем углу файла
2. Внесите изменения
3. Нажмите кнопку **«Commit changes...»**
4. В появившемся окне добавьте описание изменения и подтвердите, нажав **«Commit changes»**

#### Создание нового файла через веб-интерфейс

1. В репозитории нажмите кнопку **« + »** → **«Create new file»**
2. Введите имя файла (например, `file.md`)
3. Напишите содержимое файла
4. Нажмите **«Commit changes...»** и подтвердите дважды

#### Загрузка файлов с компьютера (Upload files)

1. Нажмите **« + »** → **«Upload files»**
2. Перетащите файлы в появившуюся область или выберите их через диалоговое окно
3. **Важно:** Можно загружать целые папки с вложенными файлами — просто перетащите папку в окно браузера
4. Добавьте описание коммита
5. Нажмите **«Commit changes»** дважды для подтверждения

### Шаг 4: Удаление файлов и папок из репозитория

#### Удаление файла

1. Перейдите в папку, где находится файл, и откройте его
2. Нажмите на значок **« ... »** (More file options) в правом верхнем углу и выберете (Delete this file) 
3. Добавьте описание коммита (например, "Удален ненужный файл")
4. Нажмите **«Commit changes»** для подтверждения

#### Удаление папки

Удалить папку через веб-интерфейс напрямую нельзя, но можно удалить все файлы внутри нее:

1. Откройте папку, которую нужно удалить
2. Удалите все файлы внутри нее по одному (как описано выше)
3. После удаления последнего файла папка исчезнет автоматически

**Альтернативный способ:** Если нужно удалить много файлов сразу, удобнее сделать это локально и  запушить изменения через Git, но это уже требует установки Git на  компьютер.

## Клонирование репозитория через скачивание ZIP-архива (простой способ)

Этот способ не требует установки дополнительных программ и идеально  подходит, если вам нужно просто скачать файлы проекта на компьютер и  посмотреть их.

### Пошаговая инструкция:

**Шаг 1. Откройте репозиторий на GitHub**

1. Зайдите на сайт GitHub и откройте нужный репозиторий (папку с проектом).

**Шаг 2. Нажмите зеленую кнопку «Code»**

1. Найдите в правой верхней части списка файлов зеленую кнопку **`<> Code`**.
2. Нажмите на нее — откроется выпадающее меню.

**Шаг 3. Выберите «Download ZIP»**

1. В открывшемся меню (обычно вкладка "Local" открыта по умолчанию) дойдите до самого низа.
2. Там будет пункт **«Download ZIP»**.
3. Нажмите на него.

**Шаг 4. Сохраните архив на компьютер**

1. Браузер начнет скачивать ZIP-архив, содержащий все файлы из репозитория.
2. Дождитесь окончания загрузки. Обычно архив сохраняется в папку «Загрузки» (Downloads).

**Шаг 5. Разархивируйте скачанный файл**

1. Откройте папку, куда сохранился архив (например, «Загрузки»).
2. Найдите скачанный файл. Его название обычно совпадает с названием репозитория (например, `мой-проект.zip`).
3. **Разархивируйте его:**
   - **На Windows:** Кликните правой кнопкой мыши по файлу → выберите **«Извлечь все...»** (Extract All...) → укажите папку для распаковки → нажмите «Извлечь».
   - **На macOS:** Просто дважды кликните по файлу — он распакуется автоматически в ту же папку.
   - **На Linux в KDE Plasma:** Через контекстное меню (как в Windows)
     1. **Откройте менеджер файлов Dolphin** (это стандартный файловый менеджер в KDE)
     2. **Найдите скачанный ZIP-файл** — скорее всего, в папке **«Загрузки»** (Downloads)
     3. **Кликните по файлу правой кнопкой мыши**
     4. В меню выберите **«Извлечь»** (Extract)
     5. Появится подменю с вариантами:
        - **«Извлечь в...»** — чтобы выбрать папку для распаковки
        - **«Извлечь сюда»** — распаковать прямо в текущую папку
        - **«Извлечь в подпапку»** — создаст папку с названием архива и распакует туда

**Шаг 6. Просматривайте файлы в менеджере файлов**

1. Откройте папку, в которую вы распаковали архив.
2. Внутри вы увидите все файлы и папки, которые были в репозитории на GitHub.
3. Теперь вы можете открывать и просматривать их с помощью стандартных программ:
   - Текстовые файлы (`.txt`, `.md`) откроются в «Блокноте».
   - Картинки откроются в «Просмотре фотографий».
   - HTML-файлы откроются в браузере.
   - Файлы с кодом (`.js`, `.py`, `.html` и др.) можно открыть любым текстовым редактором (хоть тем же «Блокнотом», но лучше скачать специальный редактор вроде VS Code).

### В чем минус этого способа?

Этот способ хорош для **однократного скачивания и просмотра** файлов. Если вы планируете вносить изменения и потом отправлять их обратно на GitHub (обновлять репозиторий), то этот способ **не подойдет**. Для работы над проектом и синхронизации изменений нужно использовать Git

Чтобы удалить репозиторий на GitHub, выполните следующие шаги:

## Шаги для удаления репозитория

1. **Войдите в GitHub** и перейдите в ваш профиль
2. **Перейдите в репозиторий**, который хотите удалить
3. **Откройте вкладку "Settings"** - она находится в правой части меню репозитория

4. **Прокрутите вниз** до раздела "Danger Zone" (Зона опасности)

5. **Нажмите "Delete this repository"**

6. **Подтвердите удаление**:
   - Введите название репозитория для подтверждения
   - Нажмите "I understand the consequences, delete this repository"

## Важные предупреждения!

⚠️ **Удаление необратимо!** После удаления:
- Весь код, issues, pull requests будут безвозвратно удалены
- Восстановить репозиторий будет невозможно
- Форки этого репозитория у других пользователей останутся

## Рекомендации перед удалением

Перед удалением рекомендуется:
- **Сделать локальную копию** если нужен код
- **Экспортировать issues/wikis** если они важны
- **Убедиться**, что репозиторий не используется в проектах

## Альтернативные варианты

Если не хотите полностью удалять:
- **Сделать приватным** - скрыть от других пользователей
- **Архивировать** - пометить как read-only
- **Переименовать** - если нужно изменить название

## Удаление через GitHub CLI

```bash
gh repo delete owner/repo-name
```

Будьте осторожны при удалении репозиториев!
